# Debate AI Deep Optimization Plan

**Goal:** Turn the existing Backchannel-derived application into a focused, German-first live debate copilot with a sub-three-second first move, restrained local compute, optional evidence research, two distinct modes, and a clearer Windows desktop experience.

**Constraints:** Preserve working audio, transcript, privacy, research and review paths. Keep exactly the two existing debate modes. Do not add another agent framework, cloud dependency, background service, or recurring cost. Use tests before behavioral changes and measure before claiming an improvement.

## Phase 1 - Evidence-backed inventory

1. Trace audio, interim/final transcript, fast response, deep analysis, research, post-call review, Windows launcher, providers, prompts and UI navigation.
2. Record each subsystem as `KEEP`, `OPTIMIZE`, `SIMPLIFY`, `REPLACE`, or `REMOVE`, with the smallest justified action.
3. Capture baseline latency, model/VRAM state, enabled live agents, prompt size, test status, and before screenshots.

## Phase 2 - External comparison

1. Compare the current streaming transcription path with current Windows-capable alternatives.
2. Compare the installed local language model and runtime with realistic RTX 4070 Laptop / 8 GB VRAM options.
3. Compare the current asyncio orchestration and deterministic evaluation approach with agent and prompt-evaluation frameworks.
4. Adopt only an alternative that clearly improves latency, reliability, quality, or maintenance without adding disproportionate complexity.

## Phase 3 - Fast path and debate quality

1. Keep the deterministic first move independent from research and slow models.
2. Reduce redundant live agents and duplicated prompt instructions while preserving deeper asynchronous revision.
3. Add a small German evaluation corpus covering attack, defense, questions, topic changes, incomplete speech, parallel discussion, evidence and unsafe overclaiming.
4. Measure transcript-to-first-move, structured local-model latency, prompt size, response length, role adherence and VRAM contention.

## Phase 4 - Product and visual redesign

1. Rebrand the visible shell around `Debate AI`, Germanize primary navigation and simplify the home state.
2. Make the currently recommended move visually dominant while retaining the required alternative move.
3. Clarify live research state, evidence, argument structure, manual refresh and post-call learning without creating a dense dashboard.
4. Capture and inspect real after screenshots at desktop and compact widths.

## Phase 5 - Verification and Windows delivery

1. Run focused tests after every change, then complete backend, frontend and desktop suites plus frontend build.
2. Re-run latency/model benchmarks and inspect Windows child-process behavior for hidden consoles.
3. Perform source-app smoke checks and a structural diff review.
4. Deliver the decision matrix, changed files, measured improvements, screenshots, verified commands and remaining limits. Stop when the smallest coherent optimized product is proven.
